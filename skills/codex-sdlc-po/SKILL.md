# Product Ownership and Backlog Management

Use when refining a product backlog, prioritizing features, writing user stories, or preparing work for implementation.

## Workflow

1. Clarify product goals, target users, evidence, strategic constraints, and the decision owner.
2. Group backlog items by user outcome rather than technical component alone.
3. Prioritize using value, urgency, risk reduction, effort, dependencies, and confidence.
4. Write stories or tasks with context, desired behavior, acceptance criteria, edge cases, and non-goals.
5. Split large items into independently testable vertical slices.
6. Remove duplicates, stale requests, and speculative work that no longer supports product goals.
7. Define readiness criteria and ensure designers/engineers/testers have necessary context.
8. Revisit priorities using actual product data and stakeholder feedback.

## Verification checklist

- Backlog is outcome-oriented.
- Priority rationale is visible.
- Acceptance criteria are testable.
- Items are small enough to deliver.
- Priorities update with evidence.

## Reporting

Report source context, decisions, work items, evidence, tests, limitations, and ownership. Do not treat a planning or coordination document as proof that implementation or release work occurred.
