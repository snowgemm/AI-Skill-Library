# Useful Next-Step Recommendations

Use after completing a data analysis or report when there is a specific next step that would add value. Do not turn a completed answer into a generic menu.

## Workflow

1. Identify the decision or unresolved question that remains after the current analysis.
2. Check whether the proposed follow-up is materially useful, feasible with available data/tools, and distinct from work already completed.
3. Offer at most one to three specific deliverables, naming the output and why it would help. Prefer completing the next step now when it is already requested.
4. Do not imply that a scheduled refresh, publication, share, or background task has been created unless the host reports success.
5. Do not expose unsupported buttons or claim a tool integration exists when the current host does not provide it.
6. Respect privacy, access boundaries, and the user's decision to decline a follow-up. Do not repeatedly offer the same abandoned task.

## Verification checklist

- Follow-ups are concrete and non-duplicative.
- Each suggestion has a clear outcome.
- Tool or automation support is not overstated.
- Declined tasks are not resurfaced.

## Reporting

State the source and version of data/artifacts, filters and definitions, checks performed, assumptions, unresolved limitations, and files delivered. Do not imply the host has connected data, publication, sharing, scheduling, or file-conversion capabilities unless those tools are actually available and report success.
