# Idea-to-Build Plan

Use when the user has an app, website, SaaS, game, or automation idea and wants to know what to build and how.

## Workflow

1. Clarify the problem, target users, existing alternatives, usage context, and what success would look like.
2. Separate the core user outcome from feature ideas. Define must-have, later, and explicitly excluded scope.
3. Write user journeys and acceptance criteria that can be tested without subjective interpretation.
4. Assess functional and non-functional needs: security, performance, reliability, accessibility, privacy, cost, and device support.
5. Compare a small number of viable technology approaches and explain trade-offs against the project's constraints.
6. Sketch architecture, data entities, APIs/integrations, permissions, deployment, and operational dependencies.
7. Break work into milestones with dependencies, risks, validation steps, and a small first vertical slice.
8. Identify open questions and assumptions that require validation before expensive implementation.

## Verification checklist

- Problem and users are concrete.
- MVP is small enough to ship.
- Acceptance criteria are testable.
- Architecture matches constraints.
- Risks and assumptions are visible.

## Reporting

Report requirements and assumptions, inspected files, architecture decisions, changes, tests/build results, and unverified areas. Be explicit about where tools, credentials, or human approvals are required. Do not claim an action was completed unless its result is observed.
