# Game Development Production Workflow

Use when creating a new game or coordinating a substantial upgrade across multiple game systems.

## Workflow

1. Inspect the current project, engine, target platforms, build pipeline, existing assets, unfinished work, and project constraints.
2. Define the player promise, core loop, controls, fail/success conditions, progression, target audience, and scope boundaries.
3. Create a small playable vertical slice before expanding content. Prove input, game state, feedback, restart, and persistence as relevant.
4. Establish visual and audio direction, asset budgets, scale conventions, collision approach, and content interfaces early.
5. Split work into gameplay, UI, world/art, audio, tools, and QA tasks with clear ownership and non-overlapping files.
6. Use versioned assets with source, license, attribution, optimization, and runtime import settings.
7. Test gameplay on target platforms, capture performance and visual evidence, and verify input/accessibility.
8. Prepare release build, controls/settings/help, known issues, backups, and deployment notes.

## Verification checklist

- Playable core loop exists.
- Art/audio integrate with runtime systems.
- Assets have provenance and license status.
- Target platform QA is performed.
- Performance and release evidence are recorded.

## Reporting

Record the project/host, asset/service identifiers, sources and permissions, actual changes, verification evidence, and limitations. Do not imply an integration is connected, an asset is licensed, or a performance improvement exists without proof.
