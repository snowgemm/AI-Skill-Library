# Software Development Lifecycle Orchestration

Use when a project requires a complete lifecycle plan or a team needs consistent checkpoints across roles.

## Workflow

1. Assess product context, existing code, stakeholders, target users, constraints, and current delivery stage.
2. Separate discovery, requirements, design, implementation, verification, release, and operations into explicit deliverables.
3. Define acceptance criteria, owners, dependencies, quality gates, and approval points for each stage.
4. Make security, privacy, accessibility, reliability, and performance cross-cutting requirements rather than final-stage add-ons.
5. Track assumptions, risks, decisions, and changing requirements in a durable project artifact.
6. Use incremental vertical slices and keep architecture proportional to the product.
7. Require evidence from tests, reviews, deployments, and user feedback before closing lifecycle gates.
8. Update plans from actual delivery status; do not represent estimates or agent claims as verified completion.

## Verification checklist

- Stages and deliverables are explicit.
- Quality and security gates are defined.
- Roles and dependencies are clear.
- Progress reflects evidence.
- Operational ownership is included.

## Reporting

Report source context, decisions, work items, evidence, tests, limitations, and ownership. Do not treat a planning or coordination document as proof that implementation or release work occurred.
