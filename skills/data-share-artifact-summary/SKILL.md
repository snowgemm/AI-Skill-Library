# Share an Artifact Summary

Use when a user asks for a short shareable explanation or handoff accompanying an analytical artifact.

## Workflow

1. Identify the audience, purpose, permitted detail, and whether the recipient can access the original artifact.
2. Read the final artifact and distinguish the main result, supporting evidence, date range, metric definitions, and limitations.
3. Write a concise summary that states the finding, why it matters, and any decision/action requested.
4. Include source and freshness information. Avoid claiming a metric is current if the artifact is stale.
5. Remove direct identifiers, private row-level information, credentials, internal URLs, and confidential notes not needed by the audience.
6. Check that the summary does not overstate causality, significance, or confidence.
7. Provide a working artifact reference only when the link exists and the recipient has appropriate permissions.

## Verification checklist

- Audience and purpose are clear.
- Main findings match the artifact.
- Date range and caveats are retained.
- Sensitive details are minimized.
- Artifact link and permissions are verified.

## Reporting

State the source and version of data/artifacts, filters and definitions, checks performed, assumptions, unresolved limitations, and files delivered. Do not imply the host has connected data, publication, sharing, scheduling, or file-conversion capabilities unless those tools are actually available and report success.
