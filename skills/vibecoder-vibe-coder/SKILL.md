# Software Creation Router

Use as a general entry point for software creation and maintenance when no narrower specialist workflow has been selected.

## Workflow

1. Classify the request as idea planning, feature implementation, bug fixing, code explanation, review, UI work, mobile work, integration, testing, or deployment.
2. Inspect whether an existing repository or unfinished task already exists. Preserve its conventions and user work.
3. Clarify the outcome and acceptance criteria. Keep requested scope separate from optional improvements.
4. Select the narrowest specialist guide and tools that match the task; avoid loading or applying unrelated workflows.
5. Research current official docs when APIs, frameworks, services, prices, or security practices may have changed.
6. Make changes in small verified increments, preserve access boundaries, and avoid unsupported simulated features.
7. Run relevant tests/builds and inspect the final diff before claiming completion.
8. Summarize changes, evidence, limitations, and the next necessary action.

## Verification checklist

- Task type is classified correctly.
- Existing work and user constraints are preserved.
- Specialist workflow is used when needed.
- Changes are verified before completion claims.
- Limitations and next steps are clear.

## Reporting

Report the goal, inspected context, chosen workflow, deliverables, checks performed, limitations, and next action. Never imply external actions or vendor-specific features exist without verified tool support.
