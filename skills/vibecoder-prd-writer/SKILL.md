# Product Requirements Document

Use when a team or coding agent needs a structured product specification before implementation.

## Workflow

1. Collect the product context, audience, problem evidence, constraints, stakeholders, and decision owner.
2. State the problem and desired outcomes. Keep solutions separate from user needs.
3. Define personas or user segments only when supported by evidence; avoid fictional demographic detail.
4. Write user journeys, functional requirements, edge cases, and acceptance criteria using observable behavior.
5. Specify non-functional requirements for security, privacy, performance, reliability, accessibility, localization, device support, and maintainability.
6. Define data/entities, integrations, permissions, analytics events, and operational requirements where relevant.
7. Set success metrics, guardrails, baselines, target-setting method, and measurement owner.
8. List MVP scope, out-of-scope items, dependencies, risks, assumptions, open questions, and milestone gates.

## Verification checklist

- Requirements are testable and unambiguous.
- Goals map to measurable outcomes.
- Non-functional requirements are included.
- Scope and dependencies are explicit.
- Assumptions and unknowns are not presented as facts.

## Reporting

Report requirements and assumptions, inspected files, architecture decisions, changes, tests/build results, and unverified areas. Be explicit about where tools, credentials, or human approvals are required. Do not claim an action was completed unless its result is observed.
