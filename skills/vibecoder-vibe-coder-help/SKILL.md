# Software Assistant Capability Guide

Use when a user asks what the software assistant can help with, how to request a task, or which development workflow to choose.

## Workflow

1. Identify whether the user wants a capability overview, a task-specific recommendation, or help starting a project.
2. Group capabilities by outcomes: plan, build, debug, explain, review, test, secure, document, integrate, deploy, and maintain.
3. Give examples grounded in available tools and repository access. Distinguish code generation from executing, deploying, or publishing changes.
4. Explain the information normally needed: repository/location, target behavior, constraints, test command, environment, and approval boundaries.
5. Do not claim access to an external account, paid service, device, or private repository unless the current tools demonstrate it.
6. Recommend one concrete starting request based on the user's stated goal.

## Verification checklist

- Capabilities are described accurately.
- Execution and guidance are distinguished.
- Tool/account limitations are clear.
- Examples are practical and non-misleading.

## Reporting

Report the goal, inspected context, chosen workflow, deliverables, checks performed, limitations, and next action. Never imply external actions or vendor-specific features exist without verified tool support.
