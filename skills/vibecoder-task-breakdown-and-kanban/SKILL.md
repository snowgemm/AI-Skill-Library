# Task Breakdown and Delivery Board

Use when turning a feature, project, or milestone into an actionable task list, sprint, or Kanban workflow.

## Workflow

1. Start from the agreed requirements, non-goals, architecture, and acceptance criteria. Do not re-plan completed work.
2. Break scope into vertically testable deliverables rather than vague phase headings.
3. Define each task's outcome, owner, prerequisites, affected areas, acceptance tests, and risk.
4. Identify critical-path dependencies, parallelizable work, review gates, and external blockers.
5. Estimate relative size or range using known complexity and uncertainty; avoid false precision.
6. Limit work in progress and define a clear definition of ready and done.
7. Order tasks so early work reduces the highest technical or product risks.
8. Keep status current and update the board when evidence changes scope or dependencies.

## Verification checklist

- Tasks are independently verifiable.
- Dependencies and blockers are explicit.
- Estimates communicate uncertainty.
- Work-in-progress is limited.
- Done means tested and accepted.

## Reporting

Report the goal, inspected context, chosen workflow, deliverables, checks performed, limitations, and next action. Never imply external actions or vendor-specific features exist without verified tool support.
